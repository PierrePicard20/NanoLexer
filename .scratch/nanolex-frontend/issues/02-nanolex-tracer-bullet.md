# 02: Minimal `nanolex` end to end

**What to build:** a first working `nanolex`. A description file with a definitions section (`%name`, `Name regex` macros) and a rules section containing only main-context rules without actions produces a lexer header whose `lex()` returns the matched lexemes. A rule pattern ends at the first unquoted, unescaped blank, as in Lex; quoted literals go through the regex syntax's own `"..."`. The reader generates internal expression names. A trailing `%%` with an empty user code section is allowed.

CLI: `nanolex file.nl -o <dir> [-l cpp]`; `-o` is resolved from the current directory; the lexer name defaults to the file base name. All errors (reader, regex parser, generation) are printed as `file.nl(line): message` (or `file.nl: message` when no line applies), regex errors pointing to the line of the rule or macro; non-zero exit status on any error.

Build: `nanolex` gets the POST_BUILD copy of `lexer_sk/` beside it, and is installed with `lexer_sk/` next to it in the install `bin/` directory.

The reader is a hand-written, line-oriented module with a small interface (description text + file name → configured `LexerGenerator` or located errors), usable from tests without the CLI.

See spec: `.scratch/nanolex-frontend/spec.md`.

## Comments

Implemented on `nanolex-frontend`.

- Reader: `nanolex/DescriptionReader.{h,cpp}`, static library `nanolex_reader` (linked by `nanolex` and by `tests`). Interface: `readDescription(text, fileName)` returns a `Description` (`std::unique_ptr<LexerGenerator>` or errors already formatted as `file.nl(line): message`, sorted by line) and `formatError()`.
- The reader creates the generator with `throwEarly`, so each failing `addMacro` / `addExpression` throws and its error is attributed to the line being processed. The ` in expression '_lexeme_N'` suffix of rule errors is stripped (the line identifies the rule); macro errors keep their ` in macro 'Name'` suffix. A consequence: `generateLexer()` stops at its first error.
- Expressions get the library's default names (`_lexeme_1`, `_lexeme_2`, ...), so the `Lexeme` enum values are `_lexeme_N_`.
- Features of later tickets are rejected with a located error for now, rather than silently ignored: text after a pattern (actions, ticket 03; `%push`/`%pop`, ticket 06), `%`-directives other than `%name` (tickets 03-06), a non-blank user code section (ticket 04). Indented lines are rejected too.
- A pattern also continues through blanks inside a character class (`[ 	]+`), as in Lex, in addition to quoted and escaped blanks.
- Library: new `LexerGenerator::getLexerName()`.
- Install: `nanolex` is in the `NanoLexerTargets` export set (`NanoLexer::nanolex`), so consumers can use `$<TARGET_FILE:NanoLexer::nanolex>` in an `add_custom_command`.
- Known limitation, shared with the `testgen` rule: the `.nl` generation rule depends on `lexer_sk/cpp/*`, but `nanolex` reads the copy made beside it at its POST_BUILD, which is only refreshed when `nanolex` is rebuilt.
- A macro whose regex fails to parse is not registered, so a rule using it also reports `Unknown macro identifier`.
