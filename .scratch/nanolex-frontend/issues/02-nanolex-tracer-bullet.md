# 02: Minimal `nanolex` end to end

**What to build:** a first working `nanolex`. A description file with a definitions section (`%name`, `Name regex` macros) and a rules section containing only main-context rules without actions produces a lexer header whose `lex()` returns the matched lexemes. A rule pattern ends at the first unquoted, unescaped blank, as in Lex; quoted literals go through the regex syntax's own `"..."`. The reader generates internal expression names. A trailing `%%` with an empty user code section is allowed.

CLI: `nanolex file.nl -o <dir> [-l cpp]`; `-o` is resolved from the current directory; the lexer name defaults to the file base name. All errors (reader, regex parser, generation) are printed as `file.nl(line): message` (or `file.nl: message` when no line applies), regex errors pointing to the line of the rule or macro; non-zero exit status on any error.

Build: `nanolex` gets the POST_BUILD copy of `lexer_sk/` beside it, and is installed with `lexer_sk/` next to it in the install `bin/` directory.

The reader is a hand-written, line-oriented module with a small interface (description text + file name → configured `LexerGenerator` or located errors), usable from tests without the CLI.

See spec: `.scratch/nanolex-frontend/spec.md`.
